# 마크다운 편집 경험 조사

## 목표와 현재 제약

Admin과 글 화면에서 하나의 문서처럼 커서를 이동하며 입력하고, 마크다운 문법이 입력 직후 화면에 반영되도록 한다. 본문 정본은 마크다운이며 Go 렌더러가 수식, 코드 라벨, 링크 카드, 애니메이션 등 블로그 확장을 처리한다. 런타임 프런트엔드 프레임워크와 자산 빌드 단계는 현재 프로젝트 제약이다.

## 가능한 접근

### 원문 기반 편집과 화면 장식

CodeMirror는 문서의 범위에 스타일을 입히거나 원문 범위를 숨기고 위젯으로 대체하는 장식을 제공한다. 커서가 있는 곳의 문법을 드러내고 나머지는 서식으로 표시하는 편집기를 만들 수 있다. 이 블로그의 확장 구문은 별도 파서와 위젯으로 구현해야 하며, Go 렌더러와 편집 중 표시의 일치를 실측해야 한다. CodeMirror의 모듈 구성과 배포 방식은 현재 자산 빌드 금지 조건과 함께 검토해야 한다. [CodeMirror 장식 예제](https://codemirror.net/examples/decoration/), [CodeMirror 예제 목록](https://codemirror.net/examples/)

### 구조화 편집 모델과 마크다운 변환

ProseMirror의 마크다운 예제는 편집용 문서 모델과 마크다운 파서·직렬화기를 사용한다. Milkdown은 ProseMirror와 Remark를 조합해 마크다운과 편집 모델을 변환하며 플러그인으로 문법을 확장한다. 이 경로는 노션처럼 서식이 적용된 내용을 직접 편집하는 경험에 가깝다. 다만 기존 글의 모든 확장과 raw HTML을 모델에 표현하거나 원문으로 보존할 수 있어야 한다. 열고 저장만 해도 원문이 변하거나 내용이 누락되는지 검증이 필요하다. 두 도구의 도입 및 배포는 현재 빌드 제약을 충족하는지 별도로 확인해야 한다. [ProseMirror 마크다운 예제](https://prosemirror.net/examples/markdown/), [Milkdown 구조](https://milkdown.dev/docs/guide/architecture-overview/)

### 브라우저 편집을 직접 구현

`contenteditable`과 입력 이벤트로 직접 편집을 만들 수 있다. 다만 `beforeinput`은 모든 사용자 변경에 발생하거나 취소 가능하다고 보장되지 않고 IME에서도 차이가 있다. 한글 조합, 선택 영역, 실행 취소, 붙여넣기를 직접 다뤄야 한다. [MDN beforeinput](https://developer.mozilla.org/en-US/docs/Web/API/Element/beforeinput_event)

## 검증할 방향

원문 기반 장식과 구조화 편집의 작은 시제품을 같은 실제 글 사본으로 비교한다. 제목·강조·목록·링크를 입력할 때 즉시 반영되는지, 문단 사이 이동과 한글 조합·실행 취소가 자연스러운지 확인한다. 수식·코드 울타리·표·HTML·애니메이션 등 기존 확장을 포함한 글은 편집 없이 열고 저장한 뒤 원문과 공개 렌더링을 비교하고, 일부만 고쳐도 다른 부분이 보존되는지 확인한다. 두 화면의 저장·충돌 검사와 모바일 접근성도 같은 시나리오로 확인한다.

서버 렌더링은 최종 미리보기의 기준으로 활용할 수 있다. 입력 중 표시의 정확도와 응답 속도는 각 시제품에서 따로 측정해야 한다.

## 노션의 키보드 편집과 시제품의 차이

노션은 `##` 뒤에 스페이스를 입력하면 제목으로 바꾸는 동작을 문서화한다. `Esc`로 블록을 선택하고 방향키로 이동하거나 `Shift`와 위아래 방향키로 범위를 넓힐 수 있다. 선택한 블록은 `Backspace` 또는 `Delete`로 지운다. 코드 블록은 `/code`와 macOS의 `⌘⌥8`이 공식 단축키 목록에 있다. 백틱 세 개 뒤에 스페이스를 입력하는 동작은 이번 시제품의 요구사항으로 두고, 빈 제목에서 `Backspace`를 눌렀을 때의 정확한 동작은 앱에서 확인할 항목으로 남긴다. [노션 키보드 단축키](https://www.notion.com/help/keyboard-shortcuts)

현재 시제품은 문단과 제목마다 `contenteditable`을 만들고 코드에는 `textarea`를 사용한다. 선택 범위를 다루는 `selectedRange`도 시작과 끝이 같은 입력칸에 있을 때만 범위를 돌려준다. 브라우저가 한 입력칸에서 글자를 지우고, 블록 자체를 지우거나 다음 입력칸으로 옮기는 동작은 시제품이 키마다 처리한다. 여러 블록에 걸친 선택과 구조 변경을 함께 되돌리는 편집 기록은 이 시제품에서 구현해야 할 별도 동작이다. [편집기 시제품](../../internal/admin/prototype/editor.html)

Chromium과 WebKit의 오프라인 실행에서 `앞 문단`을 입력한 뒤 `Enter`와 `⌘Z`를 차례로 누르면 블록 두 개가 그대로 남고 먼저 입력한 글자가 사라졌다. `Enter`가 만든 블록과 브라우저가 기록한 글자 입력이 하나의 편집 기록에 들어 있지 않기 때문이다. 두 번째 블록에 글자를 쓴 뒤 시작에서 `Backspace`를 누르면 앞 블록과 합쳐지지 않았고, `Esc`도 현재 블록을 선택하지 않았다. macOS 한글 입력기의 실제 조합 동작은 이 실행에 포함하지 않았다.

ProseMirror는 문서와 선택 범위를 같은 상태에서 관리한다. 기본 키맵의 `Backspace`는 선택 영역 삭제, 블록 경계에서의 결합, 앞 노드 선택을 순서대로 시도하고 일반 문자 삭제는 브라우저에 맡긴다. 문서 변경과 커서 갱신을 하나의 트랜잭션으로 기록할 수 있어 블록 변경도 실행 취소에 포함할 수 있다. 노션과 같은 블록 선택, 메뉴, 변환 규칙은 제품 요구에 맞게 구성해야 한다. [ProseMirror 가이드](https://prosemirror.net/docs/guide/)

다음 시제품은 한 문서의 편집 상태에서 블록 변환, 분할, 삭제, 선택과 실행 취소를 검증한다. `안녕 → Enter → ## + 스페이스`, 코드 블록 생성과 빠져나오기, 빈 문단과 빈 제목 삭제, 여러 블록 선택 후 삭제와 복구, 한글 조합 중 Enter와 Backspace를 macOS 노션 앱과 나란히 비교한다. 편집 상태를 마크다운으로 변환하는 단계에서는 바꾸지 않은 글과 수정 대상 밖의 원문을 보존할 수 있는지 확인한다.

## ProseMirror 시제품 실행

저장소 루트에서 `python3 -m http.server 18766 --bind 127.0.0.1 --directory internal/admin/static/editor`를 실행하고 `http://127.0.0.1:18766/document.html`을 연다. 공식 패키지의 배포 파일을 고정 버전으로 보관해 브라우저에서 ES 모듈로 읽는다. 패키지 버전과 라이선스는 [vendor/LICENSES.txt](../../internal/admin/static/editor/vendor/LICENSES.txt)에 있다. `prosemirror-markdown`은 시제품의 마크다운 읽기와 내보내기에 쓰고, `markdown-it`의 블록 위치는 수정하지 않은 원문 구간을 보존하는 데 쓴다.

제목과 코드 전환, 문단 나누기, 빈 블록 삭제, 블록 여러 개 선택·삭제와 실행 취소를 Chromium과 WebKit에서 확인했다. 로컬 이관 DB의 공개 아카이브 글 사본 세 건을 열고 그대로 내보낸 결과와, 수식·표·HTML·코드가 포함된 검증용 문서에서 문단 하나를 수정한 결과도 원문과 비교했다. HTML과 미지원 확장은 원문 블록으로 보존한다. Admin 편집 화면의 동작은 [아키텍처 문서](../architecture.md#section-39)에 기록한다. 실제 macOS 한글 조합은 기기에서 확인한다.

`$…$`는 문장 안의 수식으로 바뀌고, `[텍스트](URL)`은 링크가 된다. `/` 메뉴는 사진 URL, 표, 링크, 유튜브, 수식, 제목, 목록, 인용, 코드, 구분선을 삽입한다. KaTeX는 수식의 MathML 표시를, `prosemirror-tables`는 표의 셀 편집과 이동을 담당한다. 유튜브 블록은 공개 렌더러가 처리하는 독립 문단 링크로 내보내고, 시제품에서는 재생 버튼을 누를 때 플레이어를 불러온다.
